# 💈 Booking Bot — онлайн-запись в Telegram

[![CI](https://github.com/trapeezzy/telegram-booking-bot/actions/workflows/ci.yml/badge.svg)](https://github.com/trapeezzy/telegram-booking-bot/actions/workflows/ci.yml)

Telegram-бот для записи клиентов в барбершоп, салон красоты, студию или к частному мастеру.
Клиент записывается за 30 секунд без звонков, мастер получает уведомления и управляет
расписанием прямо в Telegram — без отдельной CRM.

## Возможности

**Для клиента**
- Запись в несколько касаний: услуга → дата → свободное время → подтверждение
- Показываются только реально свободные слоты с учётом длительности услуги и рабочих часов
- Телефон запрашивается один раз (кнопкой «Отправить номер» или вручную, с нормализацией формата)
- Напоминания за сутки и за час до визита
- Просмотр и отмена своих записей (не позже чем за N часов — дальше только по телефону)
- Кнопки меню работают из любой точки диалога, устаревшие кнопки не ломают бота

**Для администратора** (`/admin`)
- Мгновенные уведомления о новых записях и отменах, имя клиента — ссылка на его профиль
- Список записей на неделю с отменой в одно касание (клиент получает уведомление)
- Выходные и перерывы: закрыть день или интервал в пару касаний, плюс ежедневный обед из настроек.
  Если на закрываемое время уже есть записи, бот покажет их
- Управление услугами: добавление, скрытие из записи
- Рассылка по всем клиентам — текст, фото, видео; учёт заблокировавших бота и лимитов Telegram
- Статистика: клиенты, визиты и выручка за 30 дней, популярная услуга

**Защита от злоупотреблений**
- Лимит предстоящих записей на одного клиента — никто не займёт всё расписание
- Антифлуд: слишком частые нажатия отбрасываются до обращения к БД
- Повторная проверка слота при подтверждении: два клиента не займут одно время

## Стек

Python 3.11+ · **aiogram 3** · SQLAlchemy 2 (async) · Alembic · PostgreSQL / SQLite · Redis (FSM) ·
APScheduler · pydantic-settings · pytest · ruff · Docker Compose · GitHub Actions

## Структура

```
bot/
├── __main__.py        # точка входа: БД, диспетчер, планировщик, polling
├── config.py          # настройки из .env (pydantic-settings)
├── db/
│   ├── models.py      # User, Service, Booking, TimeOff
│   ├── repo.py        # все запросы к БД
│   ├── migrate.py     # применение миграций при старте
│   └── engine.py
├── handlers/          # роутеры: common, booking, my_bookings, admin, fallback
├── keyboards/         # inline/reply-клавиатуры и типизированные callback_data
├── services/
│   ├── slots.py       # расчёт свободного времени (чистые функции)
│   ├── reminders.py   # напоминания о визитах
│   └── notify.py      # уведомления админам и рассылка
├── middlewares.py     # сессия БД на каждый апдейт, антифлуд
├── filters.py         # IsAdmin
└── states.py          # состояния FSM
migrations/            # миграции схемы БД (Alembic)
tests/                 # unit, сквозные тесты диалогов, проверка миграций
```

## Запуск

### Docker (рекомендуется для сервера)

```bash
git clone https://github.com/trapeezzy/telegram-booking-bot.git
cd telegram-booking-bot
cp .env.example .env      # впишите BOT_TOKEN и ADMIN_IDS
docker compose up -d --build
```

Поднимутся бот, PostgreSQL и Redis. При старте бот сам применяет миграции и создаёт
стартовый набор услуг.

### Локально

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env
python -m bot
```

Без `REDIS_URL` состояние диалогов хранится в памяти, без `DATABASE_URL` используется SQLite.

### Тесты

```bash
pytest
```

Помимо unit-тестов расчёта слотов и запросов к БД, есть сквозные тесты: апдейты прогоняются
через настоящий `Dispatcher`, а Telegram API подменяется фейковой сессией. Так проверяются
целые сценарии — запись, отмена, лимиты, выходные, админка, рассылка, напоминания — без
реального токена. Отдельный тест сверяет миграции с моделями: забытая миграция не пройдёт CI.

### Изменение схемы БД

```bash
# поменяли модель в bot/db/models.py → генерируем миграцию и проверяем её глазами
alembic revision --autogenerate -m "add something"
```

Следующий запуск бота применит её сам — и локально, и на сервере.

## Настройки

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | токен от @BotFather |
| `ADMIN_IDS` | — | Telegram ID администраторов через запятую |
| `DATABASE_URL` | `sqlite+aiosqlite:///booking.db` | строка подключения SQLAlchemy |
| `REDIS_URL` | — | Redis для FSM (диалоги переживают перезапуск) |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс заведения |
| `WORK_START` / `WORK_END` | `10:00` / `20:00` | рабочие часы |
| `WORK_WEEKDAYS` | `0,1,2,3,4,5` | рабочие дни (0 — понедельник) |
| `SLOT_STEP_MINUTES` | `30` | шаг сетки времени |
| `BOOKING_DAYS_AHEAD` | `14` | на сколько дней вперёд открыта запись |
| `LUNCH_BREAK` | — | ежедневный перерыв, например `14:00-15:00` |
| `MAX_ACTIVE_BOOKINGS` | `3` | лимит предстоящих записей на клиента |
| `CANCEL_MIN_HOURS` | `2` | отмена через бота не позже чем за N часов (`0` — без ограничений) |
| `THROTTLE_SECONDS` | `0.5` | антифлуд: минимальный интервал между действиями |
| `BUSINESS_NAME`, `BUSINESS_ADDRESS`, `BUSINESS_PHONE` | — | данные для раздела «О нас» |

## Технические решения

- **Защита от двойной записи.** Слот перепроверяется при выборе и ещё раз при подтверждении
  под блокировкой — два клиента не займут одно время.
- **Миграции применяются при старте.** Обновление на сервере — это `git pull` и перезапуск,
  без ручных команд и риска забыть шаг. Схема из миграций проверяется тестом на совпадение с моделями.
- **Закрытое время — тоже «занято».** Выходные и перерывы участвуют в той же проверке
  пересечений, что и записи, поэтому обойти их нельзя даже старой кнопкой.
- **Надёжные напоминания.** Не отдельная задача на каждую запись, а одна периодическая, которая
  ищет записи по флагам в БД. Перезапуск бота не теряет и не дублирует напоминания.
- **Цена фиксируется в записи.** Изменение прайса не искажает статистику прошлых визитов.
- **Тонкие хендлеры.** SQL живёт в `repo.py`, расчёт слотов — в чистых функциях, которые
  тестируются без Telegram и БД.
- **Типизированные callback_data** вместо разбора строк вида `"slot_202611031430"`.
